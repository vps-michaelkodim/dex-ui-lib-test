## Für Designer:innen

### Storybook benutzen

- **Theme / Brand** (Toolbar oben): jede Seite zeigt sofort Dark, High Contrast oder Crimson — mit den echten Werten aus Figma.
- **Docs**-Seite je Komponente: alle Props mit ihrer Figma-Property („Figma: Variant“), live ausprobierbar.
- **Controls** (unten): Props einer Story ändern, ohne Code.
- **Design** (unten): der passende Figma-Frame direkt neben der Code-Version — zum Vergleichen (bei Figma eingeloggt sein).
- **Accessibility** (unten): automatische a11y-Prüfung der Story (Kontrast, Labels, Rollen).

### Figma → Code

1. In Figma ändern (Variablen, Styles, Icons).
2. Plugin **DDS Export** ausführen → `dds-export.json`.
3. Ein Dev (oder Claude) übernimmt sie mit `pnpm figma:import` — der Import zeigt genau, was sich geändert hat.
4. Im Pull Request sieht man die Änderungen als Diff, inkl. **Vorher/Nachher-Screenshots** der Komponenten.

Komponenten-Änderungen (neue Props, Varianten, neue Komponenten) werden von Hand im Code nachgezogen — dafür
sind die Figma-Property-Namen 1:1 die Prop-Namen.

**Warum ein eigenes Figma-Plugin?** „DDS Export“ ist der offizielle Sync-Weg fürs Team:

- **Unabhängig:** Jede:r kann den Sync machen, ohne Claude, Figma-MCP oder Enterprise-Plan
  (die Figma-REST-API liefert Variablen nur mit Enterprise).
- **Vollständig:** Ein Klick exportiert alle Variablen, Styles und die 286 Icons.
- **Nachvollziehbar:** Die Export-Datei ist ein fester Stand; der Import zeigt, was sich seit dem letzten Sync geändert hat.

Claude kann über den Figma-Zugang auch direkt einzelne Tokens übernehmen — eine Abkürzung, kein Ersatz.
Installation und Bedienung: [Plugin-README](https://github.com/vps-michaelkodim/dex-ui-lib-test/blob/main/tools/figma-plugin/README.md).

### Was Figma noch „schuldet“

Der [Gap-Report](https://github.com/vps-michaelkodim/dex-ui-lib-test/blob/main/docs/figma-gap-report.md) listet alles,
was beim Übernehmen aufgefallen ist — z.B. Farbkombinationen unter WCAG AA, Text-Styles mit falscher Schrift-Bindung,
fehlende Tokens. Nach dem Fix in Figma: Export + Import, Zeile abhaken.

### Mit AI gestalten

- **Claude-Skill „dextinity-ui“**: Claude baut Screens und Prototypen mit genau dieser Library
  (Komponenten, Token-Klassen, Regeln). Beispiel: „Bau mir im Dextinity-Playground eine Einstellungsseite mit Formular.“
- **Playground**: dort entstehen Prototypen als echte, klickbare Seiten — eine Datei in `apps/playground/src/prototypes/` reicht, Theme und Brand umschaltbar.
- **Claude Design System**: ein Abbild dieses Repos (liest das Manifest), nie eine eigene Version.

## Für Devs

### Setup

```bash
corepack enable && pnpm install
pnpm storybook                 # diese Doku, http://localhost:6006
pnpm playground                # Prototypen, http://localhost:5173
pnpm test:setup                # einmalig: Chromium für Tests
```

### Verwenden

```css
@import '@dextinity/ui/fonts.css'; /* Inter, Source Sans Pro */
@import '@dextinity/ui/styles.css'; /* Tailwind v4 + Tokens */
```

```tsx
// <html data-theme="light" data-brand="dextinity">
import { Button, Input, Tooltip, IconButton } from '@dextinity/ui';
import { EditIcon } from '@dextinity/icons';

<Input label="E-Mail" type="email" required helperText="Wir schicken dir einen Link." />
<Tooltip content="Bearbeiten" color="dark">
  <IconButton aria-label="Bearbeiten" variant="text" color="secondary"><EditIcon /></IconButton>
</Tooltip>
<Button className="mt-layout-md">Speichern</Button>
```

- Styling nur mit Token-Klassen: `bg-background-subtle`, `text-foreground-muted`, `border-border`, `typo-heading-h2-bold`,
  `rounded-surface`, `shadow-md` … Tailwinds Default-Palette ist **aus**.
- Props = Figma-Properties in camelCase; `_State` (Hover/Focus) ist kein Prop.
- Basis: React 19, [Base UI](https://base-ui.com) (Tastatur, Fokus, ARIA), Tailwind v4.
